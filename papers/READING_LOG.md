# READING_LOG.md — one paper per week, every week

> The weekly paper track. Replaces Phase 3 as a standalone phase — literature fluency is a constant, not a stage.
>
> One paper per week, read **in depth**, chosen to match the active claim wherever possible: attention papers during attention claims, compression papers during GenHash claims. The per-claim paper column is in [`../COURSE_MAP.md`](../COURSE_MAP.md).
>
> Cheat-sheets for the three papers already in `papers/` live in [`README.md`](README.md). This file is the log.

---

## The format (fixed — ≤1 page per entry)

Newest at top. Every entry, no exceptions:

```markdown
## YYYY-MM-DD · Week NN · Claim N · <Paper title> (<author year>)

**Claim it supports / why this paper now.**
One or two sentences. If it doesn't support the active claim, say why it's being read anyway.

**The core result, reconstructed.**
Code, rederivation, or hand-drawn figure — link the file. Not a summary of the abstract.
Reuse the reconstruction tasks: derive the result, reproduce a figure, or implement
the key operation. Reading without reconstructing does not count as reading.

**What I'd have to build to reimplement this.**
The honest engineering list — data, compute, components I don't have yet.

**What clicked / what is still confusing.**
Honest. "Still confusing" is expected to be non-empty. An entry where everything
clicked is a sign the paper was skimmed, not read.

**Spaced-repetition question added.**
The `REVIEW.md` ID and the question.
```

---

## Rules

1. **One per week, every week.** A skipped week is recorded as a skipped week, not backfilled later.
2. **Reconstruction is mandatory.** Code, rederivation, or a hand-drawn figure. A summary is not a reconstruction.
3. **≤1 page.** If it runs longer, the extra belongs in a module `notes.md` or an artifact post.
4. **Exactly one new `REVIEW.md` question per paper**, added the same session.
5. ***How to Scale Your Model* is the exception** — it is worked as **every exercise in pencil** (Claim 9), not as a single log entry. It gets one entry per chapter block.
6. Books (e.g. PMPP ch. 1–4) are logged in the same format; the "paper" is the chapter set.
